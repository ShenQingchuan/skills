# Create Skill

本技能用于为当前项目打造专属的私有技能，存放于项目根目录的 `.agents/skills/` 下。

它的本质是**把项目里繁琐、特殊或高频的“独门操作套路”，固化为 Agent 可以直接调用的肌肉记忆**。

---

## 核心工作铁律：严禁重新采访用户（No Re-interviewing）

- **默认行为**：直接从当前会话的上下文、讨论记录或既有代码中提取操作步骤、参数习惯和注意要点，组织成文并落盘。
- **严禁形式化提问**：不要要求用户像填表一样重新回答“这个技能叫什么、做什么、有什么步骤”。直接给出最佳草案落盘，由用户审阅修正。

---

## 物理存储规范：项目专属技能的目录结构

每个技能是 `.agents/skills/` 下的一个独立子目录，目录名采用小写字母加连字符：

```text
.agents/skills/<skill-name>/
├── SKILL.md              # 【必须】主指令入口，告诉 Agent 做什么与怎么做
├── reference.md          # 【可选】详细参考文档或专有 API 字典
├── examples.md           # 【可选】输入输出的优质范例
└── scripts/              # 【可选】现成可执行的辅助脚本
    ├── validate.py
    └── format.sh
```

## SKILL.md 编写黄金法则

### 1. 描述（Description）是路由的灵魂
每个 `SKILL.md` 顶部的 YAML Frontmatter 必须包含清晰的 `description`。它是其他 Agent 决定“用不用本技能”的唯一依据：
- **用第三人称写**（直接说明能力，严禁使用“我可以……”或“你可以……”）；
- **讲清能力（WHAT）**：说明该技能具体干什么；
- **讲清场景（WHEN）**：必须包含触发场景与关键词，便于 Agent 检索。

```markdown
---
name: db-migrate
description: 执行项目的数据库迁移与数据校验。当用户要求新增数据表、变更数据库字段、或运行数据迁移脚本时使用。
---
```

### 2. 惜字如金，不教通用常识（Concise is Key）
AI 已经掌握通用编程语言和流行工具常识，**技能文件只写本项目专属的特殊规矩、特异性步骤与踩坑经验**。主 `SKILL.md` 篇幅尽量控制在 200~300 行内。

### 3. 能跑脚本，就绝不让模型瞎编代码（Scripts First）
如果操作涉及固定的数据清洗、校验或命令串联，直接写一个 Python 或 Shell 脚本放到 `scripts/` 目录下。让 Agent 运行确定性脚本，既不会出现语法幻觉，又节省 Token。

### 4. 单层渐进式披露（Progressive Disclosure）
如果文档较长，将细节拆入同级的 `reference.md` 或 `examples.md` 中，**引用深度保持 1 层**，避免多层嵌套跳转导致上下文丢失。

---

## 标准执行流程

1. **提取操作套路**：从对话历史或用户指定的工作流中，提炼出清晰的步骤、校验规则与命令。
2. **确定技能目录**：在项目的 `.agents/skills/<skill-name>/` 下创建子目录。
3. **编写与落盘**：
   - 编写 `SKILL.md`（含标准的 Frontmatter 与清晰步骤）；
   - 若包含现成脚本，放置到 `scripts/` 目录；
   - 若有参考长文档，放置到 `reference.md`。
4. **交付成果**：通知用户文件生成路径与核心功能，请用户审阅。
