# 库与插件的 Spec 写法

库、SDK、框架插件、构建工具插件、CLI 这类项目，「用户」是调用它的开发者，「操作」是写代码或配置。这时「如何做事」一节改按下面五部分写，替换黄金路径和用户操作；「事从何来」一节不变。

## 1. API 形态

- **入口**：包名、导出路径（如 `pkg`、`pkg/vite`）、默认导出还是具名导出。
- **签名**：每个公开函数、类、组合式函数或插件工厂的完整类型签名。
- **典型调用**：一到两段最常见的用法示例，能直接复制运行。插件写清楚注册到宿主的方式。

## 2. 选项

逐项列表，每个选项写清：

| 名称 | 类型 | 默认值 | 作用 | 约束 |
| :--- | :--- | :--- | :--- | :--- |
| `include` | `string \| string[]` | `['**/*.vue']` | 参与处理的文件 | 与 `exclude` 同时命中时以 `exclude` 为准 |

另外说明：选项之间的互斥或依赖关系、非法值的报错方式、未来可能新增选项时的命名规则。

## 3. 兼容性

- **运行环境**：Node.js / 浏览器 / Bun 等版本范围，ESM 与 CJS 支持情况。
- **宿主与 peer 依赖**：插件所依赖的宿主（如 Vite、ESLint、Vue）的版本范围。
- **破坏性变更**：本次变更是否破坏现有调用；破坏时写明受影响的写法和迁移方式。
- **弃用策略**：旧 API 保留多久、用什么方式提示（类型标注 `@deprecated`、运行时警告）。

## 4. 对外契约

区分「承诺稳定」和「内部实现」，后者可以随时改：

- 公开类型与导出列表；
- 抛出的错误类型、错误码或警告文案中可被依赖的部分；
- 钩子、事件的触发时机与顺序；
- 生成产物的格式（文件结构、代码形态、sourcemap）；
- 与语义化版本的对应：哪些改动算 patch / minor / major。

## 5. 边界与验收

- **边界**：空输入、超大输入、并发调用、宿主热更新、与其他常见插件同时使用时的行为。
- **验收**：类型测试、单元测试、在真实宿主中的集成测试或示例项目；破坏性变更需要有迁移前后的对照用例。
