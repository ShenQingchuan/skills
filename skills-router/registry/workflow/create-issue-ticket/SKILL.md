# create-issue-ticket 技能指南

本技能是敏捷开发时的 **轻量任务记账工具**。

当用户在平时聊天中随口报了个 Bug、提了个改进点、或者有了个新点子时，AI 负责把它快速捕捉下来，编好号直接挂在项目任务看板上。

---

## 一、 核心铁律（不建散落文件）

- **坚决不在项目里新建任何垃圾文件**：不要新建 `TODO.md`、`task-001.md` 或 `.workflow/issues/xxx.md`；
- **唯一事实来源就是看板**：所有的待办问题，直接作为一行卡片写入项目里的 `kanban.html`；
- **轻巧不打断思路**：记完一句话反馈即可，不唠叨、不打断当前正在干的活。

---

## 二、 标准操作步骤（SOP）

### 第一步：查查看板在不在
检查当前项目根目录下是否存在 `kanban.html`：
- **如果不存在**：
  主动反引用提示用户：
  > “当前项目还没有建立任务看板，无法直接挂载卡片。建议先使用 `/manage-project-kanban`（或告诉我‘搭个任务看板’）一键初始化看板，搭好后即可随时随手记任务！”
  （若用户明确要求先建看板再记任务，可先自动完成看板初始化，再继续执行后续记账动作）。
- **如果已存在**：
  继续执行第二步。

### 第二步：自动取个简短唯一的编号
读取 `kanban.html` 里已有的卡片编号，根据用户提的事情类型自动确定前缀与序号：
- **修问题 / 报 Bug / 缺陷**：用 `fix` 前缀（如 `fix001`, `fix002`，自增递增）
- **做新功能 / 新点子**：用 `feat` 前缀（如 `feat001`, `feat002`）
- **性能 / 重构 / 杂项调整**：用 `refactor` / `perf` / `chore` 或通用的 `task`
- 确保编号在整个看板中唯一且短小好记。

### 第三步：提炼简明标题与优先级
从用户刚才说的日常口语中，提炼出一句大白话简明标题（15 字以内，把事情说明白）：
- 如果用户说了“很急”、“重要”、“马上改”，附带属性 `@{ priority: "High" }`；
- 默认放入 `backlog[待处理]` 泳道；
- 如果用户明确说了“排进排期马上做”，可直接放入 `todo[待开发]` 泳道。

### 第四步：直接写进 `kanban.html`
使用文件编辑工具，在 `kanban.html` 对应泳道下方直接插入一行卡片代码：

```text
backlog[待处理]
  fix004[登录页手机号校验报错缺失]@{ priority: "High" }
```

### 第五步：极简一句话汇报
不需要长篇大论，用一句话让用户放心即可：
> “已记到看板待处理栏：`fix004[登录页手机号校验报错缺失]`，打开看板就能看到。”

---

## 三、 常见触发口令与场景

无论是用户打命令，还是口头闲聊，AI 都应敏锐感知并唤起此技能：
- “记个 bug：手机端点开菜单会闪退”
- “/create-issue-ticket 夜间模式下边框看不清”
- “有个新想法，后面抽空做个一键导出表格功能”
- “发现一个临时待办：把这个接口的重试次数改成 3 次”
